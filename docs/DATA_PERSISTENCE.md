# LoopMuse 데이터 보관과 복원

## 기본 흐름

1. 앱은 첫 실행 때 내부 Room 데이터베이스를 자동으로 만든다. 사용자는 데이터베이스 설치 위치를 정할 필요가 없다. 음악 접근 권한은 음악 파일을 읽는 데 사용하며, 백업 폴더 쓰기 권한과는 별개다.
2. 음악 접근 권한을 받은 뒤 백업 폴더 접근을 요청한다. 권장 위치는 공유 저장소의 `내부 저장소/Documents/LoopMuse`다. Android 폴더 선택기에서 `Documents`를 허용하면 앱이 그 아래 `LoopMuse` 폴더를 사용한다. 사용자는 다른 폴더를 선택하거나 나중에 설정할 수 있다.
3. 폴더를 허용하면 앱은 그 위치의 현재·이전 백업을 먼저 확인한다. 백업 날짜와 곡 정보·재생목록·알람 수, 현재 앱과 내용이 같은지 보여주고 **복원**, **병합**, **현재 내용 그대로 사용** 중 선택하게 한다. 이전 백업이 없다면 **저장**을 누른다.
4. 결정 후 현재 앱 내용을 `loopmuse_current.json`에 저장하고 자동 백업을 시작한다. 기존 현재 백업이 있으면 별도 복구본으로 보관한 뒤 새 파일을 쓴다.
5. 설정의 **백업 및 복원** 상단에는 사용 중인 자동 백업파일 한 개만 파일명·저장일자, 전체 경로, 곡·재생목록·알람 수를 담은 카드로 표시한다. 카드 오른쪽에는 경로 **수정**만 둔다. 작은 팝업에서 새 폴더를 선택하고 **저장**하면 기존 현재·이전 백업파일은 새 위치로 검증하며 옮기고, 없으면 현재 앱 정보로 새 파일을 만든 뒤 원래 화면으로 돌아간다. 하단 **백업파일 목록**에는 사용 중인 파일을 제외한 백업본만 같은 모양의 카드로 표시하고, 오른쪽에 복원·병합·삭제 버튼을 둔다. 현재 앱과 같은 내용인지는 복원 또는 병합을 누를 때 확인하고 안내한다. **백업파일 찾아보기**는 앱 안의 탐색 팝업을 연다. 접근 허용된 폴더를 탐색하면서 상단 화살표로 이전 폴더에, 닫기 버튼으로 원래 화면에 돌아간다. 다른 저장소의 파일은 **휴대폰 파일 선택기 열기**로 Android 파일 선택기를 연다.

## 저장과 검색 시점

- 앱의 실제 작업 데이터는 내부 데이터베이스와 설정 저장소에 둔다. 공유 폴더의 JSON은 복원용 사본이다. 앱 업데이트는 내부 데이터와 공유 폴더의 백업을 유지한다.
- 자동 백업은 곡 정보, 알람, 재생목록, 선택 폴더, 재생 기록이 바뀔 때만 반응한다. 짧은 시간에 몰린 변경은 묶고, 내용이 같으면 파일을 다시 쓰지 않는다. 백업 폴더가 설정되지 않았으면 파일을 쓰지 않는다.
- 이전 파일 검색은 폴더 권한을 받고 설정하는 시점과 사용자가 **백업 및 복원**을 여는 시점에 수행한다. 평소 재생 중에는 폴더 전체를 반복 검색하지 않는다.
- 공유 `Documents/LoopMuse`는 일반적인 앱 삭제 후에도 남는다. 앱 전용 저장소는 삭제와 함께 사라지므로 권장하지 않는다. 앱을 삭제하고 재설치하면 폴더 접근 권한을 다시 받아야 한다. Android 시스템의 앱 데이터 자동 복원이 먼저 실행될 수 있으므로, 복원 필요 여부는 현재 앱 내용과 실제 백업을 비교해 표시한다.

## 파일 보호와 복원

- 새 파일은 임시 파일에 쓰고 SHA-256으로 다시 검증한 후 현재 파일을 갱신한다. 직전 정상 파일은 `LoopMuse_Recovery/loopmuse_previous.json`에 보관한다. 새 위치 설정 때 발견한 현재 파일은 고유 이름의 복구본으로 추가 보관한다.
- **복원**은 현재 앱 내용을 백업 내용으로 교체한다. **병합**은 양쪽 데이터를 합치며 중복 곡 정보는 수정 시각이 최근인 쪽을 사용한다. 복원 전에는 안전 복사본을 만든다.
- 삭제에는 확인창을 표시한다. 사용 중인 `loopmuse_current.json`은 삭제할 수 없다. 파일 선택기로 가져온 다른 백업은 저장소 제공자가 삭제를 허용할 때 삭제할 수 있다.
- 손상된 백업은 복원하지 않는다. 예전 `loopmuse_backup.json` 형식은 곡 정보 병합만 지원한다.
- 음악 파일 자체는 백업하지 않는다. 다른 기기나 달라진 경로에서 복원하면 음악 폴더를 다시 선택해야 할 수 있다.
- 저장소 제공자가 일시적으로 사용할 수 없거나 앱을 변경 직후 바로 삭제하면 마지막 변경이 반영되지 않을 수 있다. 앱을 삭제하기 전에는 설정에서 마지막 자동 백업 시각을 확인한다.
