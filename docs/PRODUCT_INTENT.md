Lounge의 게시글 탭 이름은 "공감 게시판"이고, 기존 글을 포함한 이용자 게시글에 댓글과 좋아요·싫어요를 추가한다. 목록의 기본 순서는 작성자 이름, 곡 검색 링크, 메모다. 링크가 없으면 빈 줄 없이 이름 다음에 메모가 온다. 곡 검색 링크를 메모보다 위에 더 크게 놓는다. **최신 정정**에 따라 이름 줄 오른쪽, 점 3개 메뉴 앞에는 0개도 포함해 **초록 위 엄지 버튼·숫자 → 빨간 아래 엄지 버튼·숫자 → 댓글 버튼·숫자**를 둔다. 이것이 실제 누르는 버튼이며 펼친 글 하단에 중복 버튼을 두지 않는다. 글을 펼치면 그 글의 메모가 길게 보인다. 앱 추천은 기존처럼 개인의 좋아요 켜기/끄기만 제공한다. 임의 웹 주소를 게시글에 직접 붙이는 방식과 공개 범위는 아직 확정되지 않았다.

최신 발언에 따른 **확정된 부분**: 게시글 목록은 이름 줄 → 선택적 링크 줄 → 메모 줄 순서다. 링크는 진한 청색의 더 큰 글씨다. 댓글에는 별도의 음악 링크 입력을 두지 않는다. 반응 버튼은 0개도 보이고 누를 수 있으며, 0개일 때 연하게, 1개 이상일 때 진하게 표현한다. 댓글의 이름 줄에도 같은 종류의 버튼을 둔다는 요구로 해석한다.

## 개발 판단에 사용하는 해석

아래는 원문을 작업 항목으로 옮긴 **해석**이다. 세부 규칙이 아직 확정되지 않은 부분은 임의로 정하지 않는다.

1. **핵심 재생 경험:** 기기에 저장된 음악은 사용자가 중지할 때까지 재생이 이어져야 한다. 선택한 재생 방식에서도 끊김이나 예상하지 못한 종료가 없어야 한다.
2. **기억과 되찾기:** 플레이리스트별 재생 상태와 해당 재생 주기의 곡 기록을 보존하여 이전에 듣던 곡을 다시 찾을 수 있어야 한다. 전체 재생이 끝나면 기존 주기 기록을 지우고 새 기록을 시작하는 것은 사용자가 밝힌 의도다. 과거 주기까지 별도 보존할지는 확정되지 않았다.
3. **고른 청취:** 순차 재생을 기초로 스마트·랜덤 재생을 적용하고, 그 위에 선택·좋아요·1곡 재생 옵션이 있다. 특정 곡만 반복되고 다른 곡이 빠지는 경험을 줄이는 조건은 이 계층과 플레이리스트별 주기를 기준으로 검토한다.
4. **편안한 음악 발견:** 음악에 익숙하지 않은 사용자도 좋은 곡을 발견하고 편하게 들을 수 있도록 소개와 탐색을 지원한다. “위안이 되는 음악”이라는 목적을 화면의 문구와 흐름에 반영한다.
5. **일상 알람:** 사용자가 매일 쓰는 알람을 자신의 음악과 자연스럽게 연결한다. 신뢰성이 다른 기능보다 중요하다.
6. **Lounge:** 음악을 듣는 사람들이 서버에 곡 소개와 경험을 남기고 정보를 공유한다. 로컬 재생 기능과 온라인 공유 기능의 경계를 사용자에게 분명히 알린다.
7. **앱 사용 로그인:** 앱을 처음 사용할 때 Google 계정으로 로그인한다. 이후 같은 계정을 유지하여 매번 로그인 절차를 반복하지 않게 한다. 이미 로그인한 사용자의 오프라인 재생은 네트워크가 끊겨도 계속 가능해야 한다는 개발 해석은 실제 동작을 검증한다.
8. **Lounge 운영:** 로그인한 사용자가 공동 공간에 글을 쓰고 음악을 소개한다. 누가 글을 올렸는지 운영자가 구분하고, 이용 규칙을 어긴 계정은 Lounge 참여를 막을 수 있어야 한다. 차단은 앱 전체의 오프라인 음악·알람 사용을 막는 용도로 해석하지 않는다. 서버 권한에서도 제한해야 한다.

## 아직 사용자와 정해야 할 동작

- 랜덤 재생의 스마트 켜짐·꺼짐 조합에서 곡 고르기와 주기 종료가 각각 어떻게 동작해야 하는지. 전체 재생 후 새 주기를 시작하는 원칙은 확정됐다.
- 지난 주기의 순서를 별도 이력으로 남길지. 현재 주기 기록을 초기화하는 동작 자체는 의도된 것이다.
- 앱 종료·기기 재부팅·파일 이동·폴더 변경 후 어느 범위까지 곡과 순서를 복원할지.
- 파일이 없어졌거나 재생 오류가 날 때 건너뛰고 계속 재생할지, 사용자에게 어떤 방식으로 알릴지.
- 추천곡을 앱 안의 파일과 연결하는 방식, 온라인 음악 링크를 여는 방식.
- Lounge 게시글의 공개 범위, 삭제·차단·신고 및 운영 방식.
- 게시글에 Google 계정의 이름을 표시할지, 별도의 닉네임을 표시하고 계정 식별자는 운영자에게만 보일지.
- Google 로그인 후 기존 익명 계정의 게시글을 같은 계정으로 이어받을지.

위 항목은 질문 목록이며, 현재 동작을 설명하는 문장이 아니다. 구현 확인 결과는 별도의 분석 문서와 코드에서 검증한다.

**재생 로직 변경 절차:** 먼저 현재 동작과 변경하려는 동작, 플레이리스트별 기록 및 상위 옵션에 미치는 영향, 검증 방법을 사용자에게 자세히 설명하고 확인을 받은 뒤 수정한다. 검토와 문서 정리는 코드 변경 승인과 구분한다.
