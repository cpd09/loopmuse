# LoopMuse 작업 계획

기준: [사용자가 밝힌 제품 의도](PRODUCT_INTENT.md). 이 문서는 **계획**이며, 완료된 기능 목록이 아니다.

## 현재 작업 범위

2026-09-29 최신 사용자 지시에 따라 **현재 범위는 Google Play 첫 등록 때 문제가 되는 부분을 찾고, 근거와 우선순위를 체계적으로 정리해 수정하는 작업**이다. 실제 스토어 제출은 이 작업과 구분한다. 기존 재생 로직은 전체 흐름을 이해하기 전까지 변경하지 않는다. 변경이 필요하면 현재 동작·변경안·영향·검증 방법을 자세히 설명하고 사용자 확인을 받은 뒤 진행한다. 별도 이전 대화의 마지막 작업 내용은 현재 대화와 저장소에서 확정할 수 없다.

**사용자 안내 방식:** 사용자는 비개발자 기준의 쉬운 설명을 요청했다. Firebase·Play Console에서 직접 해야 하는 일은 용어를 풀어 설명하고 한 번에 한 동작씩 안내한다. 작업을 사용자에게 넘기기 전에 저장소에서 할 수 있는 준비와 확인을 먼저 마친다.

## 바로 이어갈 순서

1. [Google Play 첫 등록 점검](PLAY_STORE_AUDIT.md)의 제출 필수·정책·실기기 검증 항목을 최신 공식 기준과 코드에 대조한다.
2. 사용자가 지정한 고유 앱 ID `com.loopmuse7205.music`의 Firebase Android 앱과 설정 파일을 확인해 `applicationId`를 변경했다. 기존 Firebase 프로젝트를 유지하고 새 Android 앱 항목을 추가했다. 이전 후보 `com.loopmuse.music`은 사용하지 않는다. 새 앱의 디버그 SHA-1과 갱신된 JSON, 새 APK의 패키지·서명을 확인했고 사용자가 Google 로그인·앱 실행·재실행 시 로그인 유지를 확인했다. 릴리스 업로드 키와 오프라인 재실행 검증은 아직 필요하다.
3. 목표 API, 릴리스 서명, 개인정보·계정 삭제, Lounge 운영·서버 규칙, 권한 신고, 로그인 심사 접근을 제출 기준에 맞춘다. 확인된 범위의 스토어 소개 문구는 먼저 수정한다.
4. 2026-09-29 20:08의 새 앱 ID 디버그 APK와 사용자 확인으로 Google 로그인·앱 실행·재실행 시 로그인 유지를 확인했다. 오프라인 재실행은 아직 확인되지 않았다. 이후 Android 16과 실제 기기에서 핵심 사용 흐름을 검증한다.
5. 재생 로직은 [읽기 전용 검토](PLAYBACK_REVIEW.md)에 기록한 상태로 유지한다. Play 제출 작업 중 재생 변경이 필요해도 사용자 확인 전에는 수정하지 않는다.

2026-09-29 코드 조사에서 확인한 내용: `PlaybackQueueManager`는 영구 플레이리스트별 재생 상태와 주기 이력을 저장하고, 스마트 재생에서 모든 대상 곡을 들으면 해당 주기 `history`를 비우고 새 주기를 시작한다. **이 초기화는 사용자 의도이며 결함으로 취급하지 않는다.** `isSingleRepeat`가 자동 다음 곡에서 먼저 적용되고, 다음으로 선택 재생, 좋아요 재생, 그 아래에서 스마트·랜덤·순차 조합이 적용된다. `MusicPlaybackService.playSong()`의 파일 열기 예외는 `false`를 반환한다. 호출 경로에 따라 재생 연속성이 달라질 수 있어 읽기 전용으로 더 확인한다. 임시 플레이리스트와 선택 상태의 저장 범위, 오류 처리 방식은 사용자 확인 없이 바꾸지 않는다.

**재생 로직 변경 승인 대기:** 현재 동작을 충분히 조사한 뒤 구체적인 수정안과 예상 영향·검증 방법을 설명한다. 사용자 확인 전에는 `PlaybackQueueManager`, `MusicPlaybackService` 및 관련 재생 코드의 동작을 변경하지 않는다.
