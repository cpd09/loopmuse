# 앱 로그인과 Lounge 운영 설계

기준: [제품 의도](PRODUCT_INTENT.md), [작업 계획](WORK_PLAN.md). 이 문서는 2026-09-29에 확인한 요구와 코드 상태를 바탕으로 한 구현 기준이다. **새 앱 ID의 Google 로그인·앱 실행·재실행 시 로그인 유지와 비행기 모드에서의 재실행은 사용자가 확인했다. 서버 차단 검증은 아직 완료되지 않았다.**

## 사용자가 확정한 범위

1. 앱을 처음 사용할 때 간단한 **Google 로그인**을 한다. Lounge만을 위한 별도 로그인은 없다.
2. 이미 로그인한 사용자는 앱을 다시 열 때마다 로그인 화면을 반복해서 보지 않는다.
3. Lounge는 곡 소개와 짧은 글로 위로와 정보를 나누는 공동 공간이다. 운영자는 작성자를 구분하고 문제 계정의 Lounge 참여를 제한할 수 있어야 한다.
4. Lounge 제한은 공동 공간의 운영 조치이며, 로컬 음악 재생과 알람 사용을 막는 앱 전체 차단과 구분한다.

## 실제 구현 순서

1. Firebase 프로젝트 `loopmuse-9991f`에서 Google 로그인 제공업체를 켜고 개발용 및 최종 배포용 앱 서명 SHA 인증서를 등록한다. 기존 앱과 신규 앱 `com.loopmuse7205.music` 모두 개발용 SHA-1과 Android·웹 OAuth 클라이언트가 갱신된 `app/google-services.json`에서 확인됐다. 사용자가 새 앱 ID에서 실제 Google 로그인을 확인했다. 최종 배포용 서명은 아직 등록되지 않았다. [Firebase 공식 설정 안내](https://firebase.google.com/docs/auth/android/google-signin)
2. 앱 시작 화면에 Google 로그인 버튼과 로그인 실패·취소·네트워크 오류 안내를 둔다. Firebase Authentication에 로그인한 사용자만 앱 화면으로 들어간다. 이미 로그인한 사용자는 저장된 세션으로 바로 앱에 들어간다. 로컬 재생·알람 데이터는 계정 전환 과정에서 삭제하지 않는다.
3. 기존 Lounge 익명 인증 이용자는 가능한 경우 익명 Firebase 사용자에 Google 자격 증명을 연결하여 같은 UID와 게시글을 유지한다. 이미 다른 Firebase 계정에 연결된 Google 자격 증명 등으로 연결이 실패하면 사용자 데이터 처리 방침을 별도로 확인한다. [Firebase 익명 계정 연결 안내](https://firebase.google.com/docs/auth/android/anonymous-auth)
4. Lounge에서 자동 익명 로그인 경로를 제거한다. 게시글에는 Firebase UID를 유지하되, 공개 표시 이름에 이메일 주소를 자동으로 넣지 않는다. 표시 이름 방식은 사용자의 답변을 반영한다.
5. 운영자 권한과 Lounge 제한 상태를 서버가 신뢰할 수 있는 곳에 보관한다. Firestore 보안 규칙은 Google 로그인 여부, 게시글 작성자 UID, 운영자 권한, 제한 상태를 확인한다. 앱 화면의 버튼 숨김만으로 권한을 판단하지 않는다.
6. 제한된 사용자는 Lounge 참여 동작을 할 수 없고, 제한 안내를 본다. 앱의 음악과 알람은 계속 이용할 수 있다. 게시글·사용자 신고와 운영 처리, 계정 및 게시글 삭제 경로를 이어서 구현한다.

## 확인 기준

- 신규 설치: Google 로그인 전에는 앱의 일반 화면으로 진입하지 않는다. 로그인 후에는 음악과 Lounge에 같은 계정으로 접근한다.
- 재실행·오프라인: 한 번 로그인한 뒤 앱을 재실행해도 로그인 화면이 반복되지 않는다. 인터넷이 없어도 로컬 음악과 알람을 사용할 수 있다. Lounge는 네트워크 오류를 분명히 안내한다.
- 기존 설치: 로컬 음악의 재생 기록, 재생 목록, 알람이 사라지지 않는다. 기존 익명 UID를 연결할 수 있는 경우 게시글 작성자 UID가 유지된다.
- 운영: 일반 사용자는 다른 사람의 글 삭제나 계정 제한을 실행할 수 없다. 제한된 계정은 별도 기기나 수정된 클라이언트로도 Firestore의 Lounge 작업을 수행할 수 없다. 운영자는 제한을 해제할 수 있다.
- 실패 처리: 로그인 취소, 네트워크 오류, Firebase 설정 누락, 계정 연결 실패가 구분되어 안내된다.

## 현재 확인한 코드 상태

- `MainActivity`는 `AppAuthGate`를 통해 Google 계정의 Firebase 세션이 확인된 뒤 `HomeScreen`을 표시한다. 2026-09-29 20:08에 새 앱 ID 디버그 APK가 생성됐고 패키지·디버그 인증서·웹 OAuth 리소스를 확인했다. 사용자는 가상폰에서 Google 로그인과 앱 실행이 정상이라고 확인했다.
- `GoogleAppAuthenticator`는 Credential Manager로 받은 Google ID 토큰을 Firebase Authentication에 전달한다. 기존 익명 사용자는 가능한 경우 같은 UID에 자격 증명을 연결한다. 충돌 시 기존 Google 계정으로 로그인하며 과거 익명 게시글은 기존 UID에 남는다.
- `CommunityViewModel`은 Lounge 진입 시 익명 인증을 하지 않는다. 글 작성자의 Firebase UID를 사용한다. 공개 표시 이름은 사용자 선택 전이라 아직 `익명`이다.
- `FirebaseCommunityRepository`의 차단 저장은 다른 사용자 필드를 보존한다. `firestore.rules`에는 Google 로그인, 관리자, 차단 상태를 검사하는 규칙을 작성했고 로컬 에뮬레이터에서 주요 허용·거부 시나리오를 통과했다. **Firebase 프로젝트에는 아직 배포되지 않았다.**
- 2026-09-29 Firebase Console에서 확인한 배포 규칙은 2026-10-20까지 모든 사람에게 Firestore 문서의 읽기·쓰기·삭제를 허용한다. 로그인 설정과 함께 새 규칙 적용이 필요하다.
- 2026-09-29 사용자가 `app/google-services.json`을 갱신했고 프로젝트·패키지·Android SHA-1·웹 OAuth 클라이언트를 확인했다. 실제 Google 로그인은 아직 시험하지 못했다.
- 이후 사용자가 같은 Firebase 프로젝트에 `com.loopmuse7205.music` Android 앱을 추가하고 새 설정 파일을 복사했다. 코드의 `applicationId`를 새 ID로 변경했다. 다시 받은 JSON에서 새 앱 항목의 디버그 SHA-1과 Android·웹 OAuth 클라이언트를 확인했다. 신규 ID APK에서 로그인·앱 실행·재실행 시 로그인 유지를 사용자가 확인했다. API 36 목표 디버그 APK를 Android 37.1 가상폰에서 비행기 모드로 다시 열었을 때도 로그인 화면 없이 음악 메인으로 들어갔고, 저장된 음악 재생과 가사 표시가 정상이라고 확인했다.
- Pixel 10 Pro Android 에뮬레이터에서 이전 설정 파일의 로그인 화면과 비활성화된 버튼을 확인했다. 이후 Android Studio가 새 앱 ID 디버그 APK를 만들었고 사용자는 Google 로그인·앱 실행·재실행 시 바로 진입을 확인했다. 이 실행 환경의 터미널 Gradle과 Android Studio 조작은 제한돼 있었다.

## Firestore 서버 규칙 적용 전 확인

2026-09-29 마지막 Firebase Console 확인에서는 2026-10-20까지 누구에게나 Firestore 문서 읽기·쓰기·삭제를 허용하는 규칙이 배포돼 있었다. 현재 배포 상태는 다시 확인해야 한다. 저장소의 [규칙 초안](../firestore.rules)은 로컬 에뮬레이터에서 Google 사용자, 익명 사용자, 제한 사용자, 관리자, 글 소유자 허용·거부 시나리오를 통과했지만 서버에는 아직 적용되지 않았다.

이 규칙을 적용하면 Google 로그인 사용자만 Lounge 게시글을 읽고 쓸 수 있다. 제한된 사용자는 게시글을 읽거나 새 글·신고를 쓸 수 없고, 작성자 또는 관리자는 해당 글을 삭제할 수 있다. 사용자 상태 변경과 신고 목록 조회는 관리자만 할 수 있다. `posts`, `reports`, `users` 이외 Firestore 컬렉션은 기본적으로 거부된다. 현재 앱 코드에서 쓰는 Firestore 컬렉션은 이 세 곳이다.

적용 위치는 Firebase 프로젝트 `loopmuse-9991f`의 **Firestore Database → 규칙** 탭이다. 현재 규칙과 저장소의 `firestore.rules`를 비교한 뒤 저장소 내용을 편집기에 넣고 **게시**한다. [Firebase 규칙 배포 안내](https://firebase.google.com/docs/firestore/security/get-started). 게시 후 로그인 계정으로 글 목록·작성·본인 글 삭제를 확인하고, 익명 접근과 다른 사용자 글 삭제가 거부되는지 시험한다. 첫 관리자 `users/<uid>` 문서는 Firebase Console 또는 Admin SDK에서 설정해야 하며 일반 앱에서는 만들 수 없다. 배포와 실제 검증이 끝날 때까지 운영 준비 완료로 표시하지 않는다.

## 남은 선택

- Lounge 공개 표시 이름: 별도 닉네임, Google 계정 이름, 또는 익명 표시 중 사용자 결정.
- 기존 익명 UID의 Google 계정 연결이 충돌할 때 게시글을 이전할지, 예전 작성자 상태로 둘지.

## 공용 Lounge 게시글과 앱 추천의 구분 (2026-09-29)

사용자는 Lounge의 짧은 글에 **댓글·좋아요·싫어요**를 요청했다. 앱 추천은 앱이 사용자에게 보여 주는 별도 공간이며, **댓글·싫어요 없이 개인 좋아요를 켜고 끄는 기능**을 유지해야 한다. `DiscoveryRecommendationsPage`의 기존 좋아요 코드는 이번 수정에서 변경하지 않았다.

Lounge의 첫 탭 이름은 "공감 게시판"이다. 곡 검색 링크를 메모보다 위에 조금 큰 글씨로 놓는다. 작성자 줄의 초록 위 엄지·숫자, 빨간 아래 엄지·숫자, 댓글 아이콘·숫자가 실제 누르는 버튼이다. 0개도 보인다. 메모를 누르면 해당 글의 본문이 펼쳐지며, 하단에 중복 반응 버튼은 두지 않는다. 화면에 보이는 설명 단어는 빼되 접근성 설명은 유지한다.

작성자·시각 줄 오른쪽, 점 3개 메뉴 앞에는 초록 위 엄지·숫자 → 빨간 아래 엄지·숫자 → 댓글 아이콘·숫자 순서로 조작 버튼을 작게 표시한다. 각각 0개여도 보인다. 댓글 수는 화면에 보이는 글의 댓글 목록을 구독해 계산하므로 공개 전 Firestore 읽기량과 좁은 화면 배치를 검증한다. 접힌 글은 메모를 최대 3줄로 보여 주며, 글이나 댓글 숫자를 누르면 전체 메모와 그 글에 달린 댓글·답글을 모두 표시한다.

최신 설명에 따라 0개 아이콘·숫자는 투명도 0.22로 매우 희미하게, 1개 이상이면 진하게 표시하도록 화면 코드를 고쳤다. 가상폰 화면에서 링크가 지나치게 커 보이고 작성자·시각이 두 줄로 갈라진다는 사용자 지적을 받아, 작성자·시각을 한 줄에 두고 링크를 `bodySmall` 13sp로 낮췄다. 링크는 밝은 화면에서 진한 청색, 어두운 화면에서는 읽기 쉬운 밝은 청색이며 최대 한 줄을 넘으면 말줄임표를 표시한다. 댓글에는 링크 입력을 두지 않는다. 댓글 이름 줄에도 좋아요·싫어요·답글 버튼을 두고, 💬은 해당 댓글에 답글을 쓰는 창을 연다. 답글에도 같은 버튼이 있어 하위 답글을 이어서 작성할 수 있다. 댓글 내용의 URL 문자열 자체를 거부할지는 아직 결정되지 않았다.

사용자가 이름 줄 상하 여백도 줄이도록 요청해 게시글 카드 안쪽 세로 여백과 반응 버튼 높이를 낮췄다. 수정한 화면의 실제 가상폰 표시와 누르기 편의성은 재검증 전이다.

Lounge 구현 초안은 `posts/{postId}/comments/{commentId}`에 500자 이내 댓글·답글과 부모 댓글 ID를 저장하고, `posts/{postId}/votes/{uid}` 및 `posts/{postId}/comments/{commentId}/votes/{uid}`에 계정별 좋아요(1) 또는 싫어요(-1) 한 값을 저장한다. 같은 버튼을 다시 누르면 투표 문서를 지우고 다른 버튼을 누르면 선택이 바뀐다. 댓글은 답글 구조를 보존하기 위해 작성자·관리자가 본문을 지우고 삭제 표시로 바꾸며, 게시글은 작성자·관리자가 하위 자료를 지운다. 댓글 신고는 기존 `reports`에 `commentId`를 추가해 구분한다.

게시글 삭제는 먼저 `isDeleting` 상태로 바꿔 추가 댓글·투표를 막고, 각 댓글의 투표·댓글·게시글 투표 문서를 나누어 지운 뒤 게시글을 제거한다. 처리 중인 글은 본문 대신 "삭제 처리 중"으로 보이고 작성자와 관리자가 다시 시도할 수 있다. 작성자가 보이는 글의 다른 사람 투표를 마음대로 지우지 못하도록 서버 규칙에서는 삭제 처리 중에만 작성자의 투표 정리를 허용한다.

**검증 상태:** 코드와 로컬 규칙 초안만 작성했다. Android Studio 빌드·화면 시험과 Firestore 에뮬레이터 권한 시험은 아직 하지 못했다. Firebase 서버 규칙은 배포되지 않았다. 삭제 중 글의 원문이 잠시 서버에 남을 수 있으며, 계정 삭제 같은 운영 상황까지 자동 처리하는 서버 절차는 아직 없다. 이 상태를 공개 준비 완료로 간주하지 않는다.

사용자가 직접 붙여 넣는 외부 URL, 댓글 수정, 공개 닉네임, 차단 기록 보존 기간은 결정되지 않았다. 현재 곡 링크는 가수명·곡명으로 만드는 YouTube 검색 링크다.
