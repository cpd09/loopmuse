# 개인정보 처리방침 작성을 위한 데이터 흐름 확인표

기준일: 2026-09-29. 코드에서 확인한 사실과 공개 전에 결정·검증할 사항을 분리한다. 이 문서는 처리방침 본문이나 Play Data safety 제출 답변이 아니다.

| 기능 | 코드에서 확인한 데이터 흐름 | 확인할 점 |
| --- | --- | --- |
| 앱 로그인 | Google Credential Manager와 Firebase Authentication으로 로그인한다. 앱은 Firebase 사용자 UID와 Google 제공업체 여부를 확인한다. Firebase 계정에는 이메일·프로필 정보가 연계될 수 있다. | Firebase 및 Google SDK의 수집·보관·공유 항목을 공식 문서와 실제 Console에서 확인. 계정 삭제 절차 결정. |
| Lounge | Firestore `posts`에 글 내용, 곡명, 가수, 링크, 작성자 UID, 표시 이름, 시각을 저장한다. 새 코드의 `posts/{postId}/comments`에는 댓글 내용·작성자 UID·시각·부모 댓글 ID·삭제 표시를, 게시글과 각 댓글의 `votes/{uid}`에는 이용자 UID별 좋아요/싫어요 선택을 저장한다. `reports`에는 신고 글 ID와 선택적 댓글 ID, 신고자 UID, 사유, 시각을 저장한다. `users`에 운영자·차단 상태를 둘 수 있다. 댓글·답글·투표는 로컬 코드 초안이며 서버 적용과 동작 검증 전이다. | 글·댓글·투표 보존 기간, 삭제 요청 시 신고·차단 기록 처리, 운영자 접근 범위와 연락처. 투표자 UID를 다른 로그인 이용자가 읽는 구조의 개인정보 안내·최소화 검토. 서버 규칙 배포 전 현재 접근 범위 재확인. |
| 기기 음악·알람·백업 | 재생 목록·이력과 알람은 기기 저장소에 저장한다. 사용자가 선택한 폴더로 백업을 내보낼 수 있다. 코드에서 음악 파일 자체를 LoopMuse 서버로 업로드하는 경로는 찾지 못했다. | 백업 위치가 다른 동기화 서비스와 연결될 가능성을 문구에 반영. 기기 파일 접근·권한 설명. |
| 온라인 가사 | LRCLIB 요청 URL에 곡명·가수명, 경우에 따라 앨범명·재생 길이를 담는다. 응답 가사는 기기에 저장된다. | 제3자 서비스와 전송 데이터 및 해당 서비스 정책 링크 확인. |
| 음악 발견 | ListenBrainz 공개 주간 통계를 HTTPS로 요청하고 응답을 기기에 캐시한다. 코드의 요청에는 사용자 음악 목록을 담지 않는다. | 제3자 서비스의 기술적 로그·접속 정보 처리 확인. |
| 외부 음악 검색 | 앱이 YouTube 검색 화면을 외부 앱/브라우저로 연다. | 외부 서비스에서의 데이터 처리는 별도임을 안내. |

기존 `legal/privacy_policy.html`의 “개인정보를 전혀 수집하지 않는다”, “서버 통신이 없다”는 현재 구현과 맞지 않아 HTML 초안으로 교체했다. 사용자는 `cpd3040@gmail.com`을 기본 운영 이메일로, `sigollo2@naver.com`을 추가 이메일로 지정했다. 두 주소의 실제 수신 시험과 보존·삭제 정책, 공개 URL을 확인한 뒤 최종 처리방침을 작성하고 앱 안에서도 접근하게 해야 한다. 기존 `sigollo@loopmuse.dev`는 사용자가 지정한 현재 연락처가 아니므로 공개 문구에서 제거했다.
