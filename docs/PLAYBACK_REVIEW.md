# 재생 로직 읽기 전용 검토

기준: [사용자 원문과 제품 의도](PRODUCT_INTENT.md), [작업 계획](WORK_PLAN.md). 2026-09-29 현재 코드를 읽고 정리했다. **재생 코드는 변경하지 않았다.** 코드에서 확인한 동작과 사용자가 밝힌 의도를 구분한다.

## 사용자가 밝힌 의도

- 플레이리스트마다 재생 정보와 곡 재생 기록을 저장한다.
- 전체 재생이 끝나면 해당 기록을 비우고 새 주기의 기록을 시작한다. 주기 초기화 자체는 의도된 동작이다.
- 순차 재생이 바탕이고 스마트·랜덤 재생이 그 위에 있다. 선택 재생, 좋아요 재생, 1곡 재생은 상위 옵션이다.
- 로직을 바꿀 때는 현재 동작과 변경안의 영향을 자세히 설명하고 사용자 확인을 받은 뒤 진행한다.

정확한 발언은 [대화 원문](conversations/2026-09-29-product-direction.md)에 그대로 보존한다.

## 변경 전에 확인할 동작

1. **재생 오류:** `MusicPlaybackService.playSong()`은 파일 열기 중 예외가 나면 `false`를 반환한다. 다음 곡으로 이어지는 처리가 모든 호출 경로에 있는지 확인해야 한다. 오류 곡을 건너뛸지, 재시도할지, 안내 후 멈출지는 사용자가 정할 동작이다.
2. **주기 경계:** 스마트 재생은 한 주기를 마치면 기록을 초기화한다. 스마트를 끈 순차·랜덤 경로는 반복되지만 기록을 비우지 않는다. 사용자가 말한 “전체재생이후”가 스마트 주기에만 적용되는지 모든 재생 방식에 적용되는지 확인이 필요하다.
3. **임시 목록과 선택 상태:** 영구 플레이리스트와 달리 `TEMP` 및 선택 상태는 재시작 시 복원되지 않는다. 임시 옵션이라는 의도인지 확인이 필요하다.
4. **재생 위치:** 현재 곡과 옵션은 상태에 있지만 일반 재생 중 곡의 밀리초 위치는 플레이리스트 상태에 저장하지 않는다. “재생 정보”의 범위에 위치가 포함되는지 확인이 필요하다.

## 검증 순서와 변경 승인

수정안을 만들기 전에 각 영구 플레이리스트에서 순차/스마트/랜덤 조합과 선택·좋아요·1곡 옵션을 켜고 끄는 경우를 확인한다. 주기 끝, 이전·다음 이동, 앱 재시작, 없는 파일도 별도로 본다. 오류 또는 요구와 다른 동작을 발견하면 **재현 방법, 현재 결과, 바꿀 결과, 다른 옵션과 저장 데이터에 미치는 영향, 확인 방법**을 제시하고 사용자 확인을 받은 뒤 재생 코드를 수정한다.
